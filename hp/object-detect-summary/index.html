Object Detect

Summary

Take-home deliverable for a Principal Product Marketing Manager, AI Solutions interview (round 4): a local object detection/counting application for a manufacturing or robotics use case, plus a short presentation on performance and customer positioning.

Watch First

A short walkthrough of this project, in my own words — the fastest way to understand what it is and why it's built this way before digging into the ten levels below.

Rather than one app, this is a progressive series of ten "levels" demonstrating increasing technical sophistication (classical computer vision → learned classifiers → deep learning → open-vocabulary detection → video tracking → hardware-scaling analysis).

Environment
Runs locally, not in the cloud.
  • macOS, Intel-based MacBook Air — not Apple Silicon, which mattered a lot for package compatibility.
  • Python 3.11 in a project-local venv, downgraded from 3.13 because PyTorch dropped Intel Mac support starting at version 2.3 — torch==2.2.2 was the last compatible version, which constrained every downstream package choice: numpy pinned <2 to match torch 2.2.2's expected ABI, opencv-python pinned <5 (v5 moved Haar cascades to a contrib-only module), transformers pinned to 4.46.3 (newer versions require torch>=2.5).
Level Roadmap
Ten graduated levels, from classical computer vision to a forward-looking hardware-scaling analysis.
Level Approach Status
1 Haar Cascade — classical, fixed rules (faces) Done
2 HOG + SVM — learned classifier, hand-crafted features (pedestrians) Done
3 YOLOv8 — deep learning, general-purpose (COCO, 80 classes) Done
4 YOLOv8 on a real manufacturing scene — the vocabulary-gap pivot Done
5 YOLO-World — open-vocabulary detection, any object by text prompt Done
6 Grounding DINO — stronger open-vocabulary detection Done
7 Video object tracking + unique counting (ByteTrack) Done
8 Video speed estimation + CSV data export Done
9 Writeup: scaling to the HP ZGX Nano AI Station Done
10 Writeup: scaling to the HP ZGX Fury AI Station Done
Overall Narrative Arc

Technical progression: fixed classical rules (L1) → learned classifier on fixed features (L2) → fully learned deep learning (L3) → open-vocabulary/zero-shot (L5, L6) → temporal/video (L7, L8) → hardware-scaling forward look (L9, L10).

Consistent theme: every level includes an honestly documented limitation or failure, not just wins — tilted faces missed in L1, a deliberately-kept zero-detection result in L2, a wrong-viewpoint failure in L3, COCO's missing industrial vocabulary in L4, imprecise language-matching in L5, heavy compute cost in L6, a motorcycle-filtering oversight in L7, explicitly-flagged approximate speed in L8.
