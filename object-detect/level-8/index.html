Level 8 — Video Speed Estimation + Data Export

Extends Level 7's tracking with per-vehicle speed estimation and a structured, exportable data pipeline.

Done
Approach
Extends Level 7's tracking with per-vehicle speed estimation and a structured data extraction pipeline.
# Pixel displacement between tracked positions / calibrated pixels-per-meter / elapsed time
pixel_dist = ((x_new - x_old)**2 + (y_new - y_old)**2) ** 0.5
meters_per_sec = (pixel_dist / PIXELS_PER_METER) / seconds
mph = meters_per_sec * 2.23694

Explicitly stated as an approximation — true speed requires real camera calibration (e.g., a surveyed lane-width reference), which is stated both in the on-screen video overlay and in terminal output. That honesty is a deliberate part of the narrative: an uncalibrated number presented as precise would undermine credibility the moment someone asks how it was calibrated.

Visual feature: bounding boxes turn red above a configurable mph threshold, green at or below it — recalculated fresh every frame per vehicle, so it toggles live and accurately reflects current speed.

The "Total vehicles tracked" figures below (e.g. 46 in clip 1) are unique track IDs from the same BoT-SORT tracker as Level 7, not a verified physical count — an upper bound, since an occluded vehicle that gets reacquired under a new ID is counted twice. See Level 7 for the full explanation and the production alternative (line-crossing / zone counting).

Data extraction pipeline
  • Full per-vehicle speed history collected across the entire video — every reading, every frame, per tracked ID.
  • End-of-run printed summary table: vehicle ID, class, avg/max/min mph, frames tracked, over-threshold flag.
  • CSV export — a genuine structured, exportable data artifact, not just a video to watch once.

The video isn't just producing a visual — it's extracting structured, exportable data per object, exactly the kind of output a real manufacturing or logistics deployment would need to feed into a dashboard or reporting system.
